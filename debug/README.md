# 偵錯腳本說明 (Debugging Scripts Guide)

本目錄 (`debug/`) 存放一系列遵循 `BUG.MD` 中「鳳凰之心協定」設計原則的「黃金標準」偵錯腳本。

這些腳本的目標是在一個可控的本地環境中，精準、獨立地重現和測試核心應用程式的特定流程，以確保後端的穩定性。

## 核心原則

- **獨立性**: 每個腳本都應盡可能獨立，自行處理環境設定，以確保測試的可重現性。
- **清晰性**: 腳本包含詳細的日誌輸出，清楚地標示出其執行的每一個階段。
- **確定性**: 在相同的程式碼版本下，腳本的執行結果應該是穩定且可預測的。

---

## 腳本說明

### 1. `colab_runner_debug_1.py`

- **核心功能**: 驗證後端核心服務的啟動流程是否健全。
- **執行內容**:
    1.  建立一個完全獨立的虛擬環境 (`.venv_debug`)，若已存在則會先刪除以確保純淨。
    2.  讀取 `requirements/dev.txt` 並安裝所有必要的開發依賴。
    3.  啟動後端 Uvicorn 伺服器 (`src.phoenix_core.main:app`)。
    4.  **內建看門狗 (Watchdog) 機制**: 在背景監控後端服務的日誌輸出。如果在指定時間內（預設 30 秒）沒有任何活動，則會判定服務已卡死或啟動失敗，並自動終止腳本。
- **使用方法**:
    ```bash
    # 從專案根目錄執行
    python debug/colab_runner_debug_1.py
    ```

### 2. `report_debug_1.py`

- **核心功能**: 驗證報告生成前的「資料庫準備」流程是否正確。
- **執行內容**:
    1.  確認由 `colab_runner_debug_1.py` 所建立的 `.venv_debug` 虛擬環境是否存在。
    2.  檢查專案根目錄下是否存在 `state.db` 資料庫檔案。
    3.  如果 `state.db` **不存在**，腳本會自動建立一個包含假資料的 `state.db` 以便進行獨立測試。
    4.  執行一項關鍵操作：將 `state.db` **重新命名**為 `logs.sqlite`。
- **使用方法**:
    ```bash
    # 建議在 colab_runner_debug_1.py 執行成功後運行，
    # 或者手動建立 .venv_debug 環境後運行。
    python debug/report_debug_1.py
    ```

#### **重要：為何此腳本沒有實際產生報告？**

在您執行 `report_debug_1.py` 後，您會看到一條訊息解釋腳本的執行到「資料庫重命名」後即中止。這是**符合預期的行為**。

- **原因**: 經過對當前專案程式碼的深入分析，我們發現原先用於生成報告的獨立腳本 (`scripts/generate_report.py`) 已經在近期的版本中被**重構或移除**。
- **目的**: 因此，這個偵錯腳本的目標也隨之調整，專注於驗證其**前置任務**——也就是資料庫的準備與重命名——是否能成功執行。
- **結論**: 成功執行此腳本，代表著資料管線中，從「應用程式產生資料庫」到「準備好可供報告的資料庫」這一段是健康且正常的。

## 建議執行流程

1.  先執行 `python debug/colab_runner_debug_1.py` 來驗證後端服務本身。
2.  (可選) 手動檢查是否有 `state.db` 被後端服務成功建立。
3.  再執行 `python debug/report_debug_1.py` 來驗證資料庫的後續處理流程。
