# 偵錯腳本說明 (Debugging Scripts Guide) V2

本目錄 (`debug/`) 存放一系列遵循 `BUG.MD` 中「鳳凰之心協定」設計原則的「黃金標準」偵錯腳本。

這些腳本的目標是在一個可控的本地環境中，精準、獨立地重現和測試核心應用程式的特定流程，以確保後端的穩定性與檔案下載的通順性。

## 核心原則

- **獨立性**: 每個腳本都應盡可能獨立，自行處理環境設定，以確保測試的可重現性。
- **清晰性**: 腳本包含詳細的日誌輸出，清楚地標示出其執行的每一個階段。
- **確定性**: 在相同的程式碼版本下，腳本的執行結果應該是穩定且可預測的。

---

## 腳本說明

### 1. `colab_runner_debug_1.py` (含下載驗證)

- **核心功能**: 驗證遠端 Git Repo 下載通順性，並檢查後端核心服務的啟動流程是否健全。
- **執行內容**:
    1.  **(新增) 下載驗證**:
        - 從遠端 Git 儲存庫 (`https://github.com/hsp1234-web/WEB_0802.git`) 的 `0.4.5` 分支下載程式碼。
        - 程式碼會被下載到一個**臨時隔離目錄** (`temp_clone_dir_for_validation`)。
        - 驗證下載成功後，會**立即刪除**該臨時目錄，確保不污染本地開發環境。
    2.  **環境準備**: 建立一個完全獨立的虛擬環境 (`.venv_debug`)，若已存在則會先刪除。
    3.  **依賴安裝**: 讀取 `requirements/dev.txt` 並安裝所有必要的開發依賴。
    4.  **服務啟動**: 啟動後端 Uvicorn 伺服器 (`src.phoenix_core.main:app`)。
    5.  **看門狗監控**: 在背景監控後端服務的日誌輸出，若在指定時間內無活動則判定為失敗。
- **使用方法**:
    ```bash
    # 從專案根目錄執行
    python debug/colab_runner_debug_1.py
    ```

### 2. `report_debug_1.py`

- **核心功能**: 驗證報告生成前的「資料庫準備」流程是否正確。
- **執行內容**:
    1.  確認由 `colab_runner_debug_1.py` 所建立的 `.venv_debug` 虛擬環境是否存在。
    2.  檢查專案根目錄下是否存在 `state.db` 資料庫檔案。
    3.  如果 `state.db` **不存在**，腳本會自動建立一個包含假資料的 `state.db` 以便進行獨立測試。
    4.  執行一項關鍵操作：將 `state.db` **重新命名**為 `logs.sqlite`。
- **使用方法**:
    ```bash
    # 建議在 colab_runner_debug_1.py 執行成功後運行。
    python debug/report_debug_1.py
    ```

#### **重要：為何 `report_debug_1.py` 沒有實際產生報告？**

這是**符合預期的行為**。經過對當前專案程式碼的分析，原先用於生成報告的獨立腳本已被重構或移除。因此，此偵錯腳本的目標也隨之調整，專注於驗證其**前置任務**——也就是資料庫的準備與重命名——是否能成功執行。

## 建議執行流程

1.  執行 `python debug/colab_runner_debug_1.py` 來驗證下載與後端服務。
2.  執行 `python debug/report_debug_1.py` 來驗證資料庫的後續處理流程。
